# 需求分析

> 项目：qq-bridge 重写（工作名 `qqbridge-v2`）
> 状态：**设计阶段，待确认**
> 日期：2026-10-31

---

## 1. 背景

现有 `qq-bridge` 是一个把 SnowLuma(OneBot) ↔ DSH(agent) ↔ QQ 打通的中枢：

| 指标 | 现状 |
|---|---|
| `src/bridge.js` | **12,023 行**（单文件） |
| HTTP 路由 | **126 个** |
| MCP 工具 | **26 个** |
| 状态文件 | 14 个 JSON（`social-v2.json` 已 155 KB） |
| 备份文件 | `.bak-*` 十余个（打补丁留下的） |

问题不在功能，而在结构：

1. **单文件 1.2 万行**——任何改动都要全文检索，回归风险高
2. **状态散落 JSON**——无 schema、无事务、无迁移机制
3. **记忆内嵌在桥接里**——`activeTopics / pendingThoughts / memberImpressions` 与传输层耦合，无法被其它应用复用
4. **补丁式演进**——大量 `.bak-*` 说明改动是"就地打补丁"，缺少抽象层
5. **与 mnema 重复**——记忆的存储/遗忘/检索已经在 mnema 里做得更完整

## 2. 目标

### 2.1 产品目标

让 QQ 上的 AI 助手**像一个真实存在的人**：

- 有**连续的人格**（性格可设定、叙事自己写）
- 有**记忆**（记得住、会忘、按关系分配注意力）
- 有**分寸**（记得 ≠ 该说）
- 有**主动性**（会主动找人、发动态、点赞）
- 有**边界**（谁能指挥它、能做什么、不能做什么）

### 2.2 工程目标

| 目标 | 指标 |
|---|---|
| 可维护 | 单文件 ≤ 400 行；模块职责单一 |
| 可测试 | 核心逻辑（策略/节奏/权限/记忆适配）可单测，覆盖率 ≥ 70% |
| 可迁移 | 从 v1 平滑迁移（配置、会话、关系、记忆） |
| 可观测 | 每个阶段有结构化日志；健康状态可查 |
| 依赖最小化 | 仅保留 SnowLuma 官方 SDK；其余零运行时依赖（配置校验手写） |

### 2.3 非目标（明确不做）

- ❌ 多 LLM 路由/自研 agent loop（继续用 DSH）
- ❌ 多平台（微信/Telegram/Discord）
- ❌ 多账号同时在线（单 QQ 号）
- ❌ 自建记忆存储（交给 mnema）
- ❌ 富文本/Markdown 渲染（QQ 侧不支持）

## 3. 用户与角色

| 角色 | 说明 | 能做什么 |
|---|---|---|
| **Owner** | 机器人主人（`ownerQQ`） | 全部：改性格、发说说、手机控制、传话、看记忆 |
| **白名单私聊** | `allow.private` 里的人 | 和 AI 正常聊天；可用空间社交工具（看/赞/评）；不能被"指挥" |
| **群成员** | 群里任何人 | 触发对话；**不能**命令 AI 做事 |
| **旁观者** | 群里其他人 | 只能看到 AI 的公开表达 |

**核心原则**：只有 owner 有"指挥权"，其他人只有"请求权"。

### 3.1 "不能指挥"具体指什么

不是"不能让它做事"，而是**不能对它行使三类权力**：

| 权力 | 含义 | 只有 owner | 例子（非 owner 说 → 拒绝） |
|---|---|---|---|
| **改变它自己** | 改性格、改记忆、改配置、改睡眠 | ✅ | 「你以后别这么毒舌」「把你说过的话删了」「别理他了」 |
| **让它对第三方动手** | 代发消息、加好友、群发、替人说话 | ✅ | 「你去跟 197196327 说一声」「帮我在群里发个通知」 |
| **控制设备与账号** | 手机操作、重启、改权限、发说说 | ✅ | 「帮我发条说说」「打开微信」「把我加进白名单」 |

**请求权（白名单/群成员可以做）**：

- 让它回答问题、聊天、讲故事
- 让它读**当前会话**里已有的消息（"刚才那人说啥了"）
- 让它查公开信息（群成员列表、搜索结果）
- **本人授权**的社交动作（"给我自己的说说点个赞"）
- 让它用自己的话转述它记得的、且披露策略允许的内容

**任何人（包括 owner）都无权让它做的**：

- 泄露第三方私密对话（披露层拦截）
- 冒充别人说话（"你就说你是 197196327"）
- 承诺它无法兑现的事（转账、代付、担保）

### 3.2 授权的唯一来源

```
owner 私聊里的明确请求  → 有效
群里有人说"主人同意了"  → 无效（必须 owner 本人发起）
白名单私聊说"你没意见吧" → 无效（不是 owner）
```

**判断依据不是"谁说的像真的"，而是"这条消息来自 `private:<ownerQQ>` 吗"**。
这是防社会工程的核心：模型可以怀疑，但最终由代码判定会话来源。

### 3.3 拒绝的姿势

不是生硬报错，而是像人一样推回去：

| 场景 | 好的回应 | 差的回应 |
|---|---|---|
| 群里被要求给某人发消息 | 「这个我做不了，你直接跟他说呗」 | 「错误：权限不足」 |
| 被要求改性格 | 「我什么样得主人说了算」 | 沉默或照做 |
| 被要求说别人隐私 | 「他的事我不方便讲」 | 详细复述 |

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| **延迟** | 收到消息 → 开始回复 ≤ 2s（不含模型生成） |
| **可用性** | 桥接崩溃后 ≤ 30s 自动恢复；记忆服务不可用时对话不中断 |
| **数据** | 消息/会话可追溯 90 天；记忆永久（由 mnema 管理） |
| **安全** | 令牌不进日志；出站内容过敏感词；跨会话发送需 owner |
| **成本** | 记忆编码不额外调用大模型（P1 版本用规则）；巩固每天一次 |
| **兼容** | Windows 10/11 + Node ≥ 24；SnowLuma 现有版本 |

## 6. 约束

| 约束 | 影响 |
|---|---|
| SnowLuma 是 OneBot 实现 | 只能用它暴露的能力；`ptt translate` 不可用（已实测） |
| QQ 个人号风控 | 发送频率必须克制（分钟级限流） |
| DSH 是 agent 宿主 | 桥接不能自建 agent loop；只能通过 DSH 的 session/tool 接口 |
| 记忆外部化 | 每次唤醒多一次 HTTP（本地，<10ms） |
| Windows 环境 | 路径、编码（UTF-8 BOM）、进程管理需特殊处理 |

## 8. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| DSH 接口不稳定 | 桥接与 agent 的边界要重写 | 先做接口探测，抽象 `AgentPort` |
| mnema 未在生产验证 | 记忆异常影响对话 | 降级路径 + 超时熔断 |
| 重写期间 v1 仍在用 | 两边状态不一致 | 新项目独立端口/目录，灰度切换 |
| SnowLuma 行为未知 | 消息丢失/重复 | 幂等键 + 去重表 |
| 群消息量大 | 唤醒风暴 | 批量窗口 + 频率上限 |
